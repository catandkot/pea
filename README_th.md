# 🫛 PEA

### สมาร์ทฟาร์มเอเจนต์ — อ่านข้อมูลจากแปลงเพาะปลูก ตัดสินใจ และลงมือทำ

PEA (ถั่ว) คือ **สมาร์ทฟาร์มเอเจนต์** สำหรับแปลงปลูกในโรงเรือนและแปลงกลางแจ้ง รวบรวมค่าจากเซนเซอร์ทั้งความชื้นในดิน อุณหภูมิและความชื้นสัมพัทธ์ ปริมาณแสงสะสม และค่า EC/pH ของน้ำระบาย เพื่ออธิบายว่า *ตอนนี้กำลังเกิดอะไรขึ้น* และควบคุมอุปกรณ์อย่างการให้น้ำ การระบายอากาศ การพรางแสง และการเสริมแสง **ภายในขอบเขตที่ปลอดภัย**

ทุกการตัดสินใจมีหลักฐานกำกับ PEA แยกและรายงาน **ค่าที่สังเกตได้** **ค่าที่อนุมานได้** และ **ค่าที่ยังไม่รู้** อย่างชัดเจน "ดินแห้ง" คือข้อมูลจากประวัติเซนเซอร์ "ช่วงบ่ายมีความเสี่ยงสูงที่จะเกิดอาการยอดไหม้" คือการอนุมาน และ "วาล์วน้ำเปิดจริงหรือไม่" ยังเป็นค่าที่ไม่รู้จนกว่าเครื่องวัดอัตราการไหลจะยืนยัน

งานทั้งหมดจบในฟาร์ม ข้อมูลที่ออกสู่ภายนอกมีเพียงรายการที่ผู้ใช้เลือกไว้อย่างชัดเจนเท่านั้น

## เริ่มต้นอย่างรวดเร็ว

> **ชื่อคำสั่งและชื่อแพ็กเกจด้านล่างนี้ยังไม่เป็นข้อยุติ** ปัจจุบันยังไม่มีแพ็กเกจ `pea` เผยแพร่บน npm เราจะปรับปรุงเอกสารนี้ให้เป็นคำสั่งจริงเมื่อถึงเวลาที่เผยแพร่

```bash
# 1) install (package not published yet)
npx pea-agents setup

# 2) readiness check — gateway, sensors and actuators
pea doctor

# 3) ask about today's greenhouse
pea analyze ./farm.toml
```

เมื่อเชื่อมต่อกับเอเจนต์แล้ว ก็ถามแบบนี้ได้เลย

```text
โรงเรือนที่ 3 ช่วงเช้าให้น้ำเกินเป้าไป 12% เพราะอะไร?
ถ้าจะให้อัตราการระบายน้ำอยู่ที่ 25% ต้องปรับตารางให้น้ำช่วงบ่ายวันนี้อย่างไร?
ขอดูระยะเวลาที่ใบเปียกต่อเนื่อง โดยอิงจากอุณหภูมิต่ำสุดเมื่อคืนนี้ว่ากี่ชั่วโมง
```

## ทำอะไรได้บ้าง

| ขอบเขต | สิ่งที่ PEA ทำ | ข้อมูลที่ใช้ |
| --- | --- | --- |
| สภาพการเจริญเติบโต | แสดงแนวโน้มและช่วงที่ผิดปกติของอุณหภูมิและความชื้นในโรงเรือน, VPD และปริมาณแสงสะสม | เซนเซอร์อุณหภูมิและความชื้น, เครื่องวัดปริมาณแสง |
| การให้น้ำและสารอาหาร | คำนวณปริมาณน้ำจากการสะสมของปริมาณแสง, แจ้งเตือนเมื่ออัตราการระบายเบี่ยงเบนจากเป้าหมาย | เซนเซอร์ความชื้นในดินและเครื่องชั่งน้ำหนัก, ค่า EC/pH ของน้ำระบาย |
| การระบายอากาศและควบคุมอุณหภูมิ | ควบคุมให้คงเป้า VPD ไว้, เสนอระดับการเปิดช่องระบายอากาศและพัดลม | ข้อมูลตอบกลับการเปิดหน้าต่าง, สภาพอากาศภายนอก |
| แจ้งเตือนโรคและแมลง | คำนวณความเสี่ยงโรคเชื้อราจากระยะเวลาที่ใบเปียกและอุณหภูมิร่วมกับความชื้น | ประวัติอุณหภูมิและความชื้น, เซนเซอร์ความเปียกใบ |
| บันทึกการเจริญเติบโต | บันทึกประวัติการให้น้ำ สภาพแวดล้อม และงานในแปลงอัตโนมัติ, ช่วยกรอกข้อมูลสำรวจการเจริญเติบโต | บันทึกงาน, ภาพถ่ายภาคสนาม |
| พยากรณ์การเก็บเกี่ยว | ประมาณช่วงเวลาเก็บเกี่ยวจากอุณหภูมิสะสม, เปรียบเทียบระหว่างรุ่นการเพาะปลูก | ประวัติอุณหภูมิ, พารามิเตอร์พันธุ์พืช |

รายการและค่าเกณฑ์ในตารางเป็น **ค่าที่ต้องปรับเทียบใหม่ตามพืช พันธุ์ และพื้นที่** PEA เพียงเสนอค่าเริ่มต้น ไม่ยืนยันว่าเป็นค่ามาตรฐานของฟาร์มนั้น

## วิธีการทำงาน

เมื่อเอเจนต์ถาม PEA ผ่าน MCP, PEA จะรวบรวมข้อมูลจากเกตเวย์และส่งผลลัพธ์กลับพร้อมหลักฐาน เอเจนต์นำผลลัพธ์นั้นไปอธิบายสถานการณ์หรือเสนอแนวทางควบคุม เวิร์กโฟลว์เดียวกันนี้ใช้ผ่าน CLI ในเทอร์มินัลได้เช่นกัน

```text
เอเจนต์ → MCP → PEA → เกตเวย์ → เซนเซอร์
                     ← ค่าที่สังเกต + การอนุมาน + ค่าที่ยังไม่รู้
```

- **ท้องถิ่นก่อน** — การเก็บข้อมูลและการตัดสินใจประมวลผลภายในฟาร์ม
- **หลักฐานก่อน** — เก็บค่าดั้งเดิม เวลา และแหล่งที่มาไว้พร้อมกับข้อสรุป
- **ไม่รู้คือไม่รู้** — ช่วงที่ไม่มีเซนเซอร์หรือการสื่อสารขาดหาย จะระบุไว้อย่างชัดเจน ไม่เติมด้วยการคาดเดา
- **ผลลัพธ์เดียวกัน** — CLI และ MCP ใช้เวิร์กโฟลว์และสัญญาผลลัพธ์เดียวกัน

## สิ่งที่รองรับ

| การเชื่อมต่อ | วิธี | สถานะ |
| --- | --- | --- |
| เกตเวย์ MQTT | เก็บท็อปิกของเซนเซอร์ด้วยการสมัครรับจากโบรกเกอร์ | วางแผนไว้ |
| Modbus RTU / TCP | โพลล์รีจิสเตอร์ของตัวควบคุม | วางแผนไว้ |
| LoRaWAN | เซนเซอร์ภาคสนามผ่านเกตเวย์ | วางแผนไว้ |
| ข้อมูลอุตุนิยมวิทยา | API อุตุนิยมวิทยาท้องถิ่น, อุณหภูมิ ความชื้น และปริมาณฝนภายนอก | วางแผนไว้ |
| ระบบจัดการการเพาะปลูกที่มีอยู่ | รวมประวัติด้วยการนำเข้าไฟล์ (CSV/JSON) | วางแผนไว้ |

## หลักความปลอดภัย

การสั่งงานอุปกรณ์เป็นสิ่งที่ย้อนกลับไม่ได้ PEA จึงยึดหลักต่อไปนี้

1. **ต้องมีคนอนุมัติเป็นค่าเริ่มต้น** — การทำงานจริงอย่างการให้น้ำ การระบายอากาศ และการเสริมแสง จะพิมพ์แผนออกมาก่อนและรอการอนุมัติ
2. **ขีดจำกัดแข็ง** — เพดานที่ตั้งไว้สำหรับฟาร์ม (เช่น ปริมาณน้ำสูงสุดต่อครั้ง ช่วงอุณหภูมิที่อนุญาต) เอเจนต์ตัดสินใจข้ามไม่ได้
3. **ปลอดภัยไว้ก่อน** — เมื่อการสื่อสารขาดหายหรือไฟดับ ระบบจะเข้าสู่ฝั่งปลอดภัย (หยุดให้น้ำ เปิดระบายอากาศ ฯลฯ)
4. **ไม่พ่นสารอัตโนมัติ** — PEA ไม่ฉีดพ่นยาและปุ๋ยเอง เพียงเสนอช่วงเวลาและเหตุผล
5. **บันทึกครบทั้งหมด** — ทุกการควบคุมจะบันทึกเป้าหมาย เวลา หลักฐาน และผลการทำงานไว้

## แผนงาน

- **M0 — คอนเซปต์และเอกสาร** *(ปัจจุบัน)*: นิยามผลิตภัณฑ์ หลักความปลอดภัย และการออกแบบสัญญาผลลัพธ์
- **M1 — การเก็บข้อมูล**: เชื่อมต่อเกตเวย์ จัดเก็บประวัติเซนเซอร์ และดูแนวโน้มสภาพแวดล้อม
- **M2 — คำแนะนำ**: ตัวช่วยแนะนำการให้น้ำและการระบายอากาศ ความเสี่ยงโรคและแมลง และบันทึกการเจริญเติบโตอัตโนมัติ
- **M3 — การควบคุมโดยมีคนอนุมัติ**: การควบคุมอัตโนมัติภายใต้การอนุมัติของคนและกลไกปลอดภัยไว้ก่อน
- **M4 — การดำเนินงาน**: พยากรณ์การเก็บเกี่ยว เปรียบเทียบหลายฟาร์ม และรายงานรายรุ่นการเพาะปลูก

## สถานะของโครงการ

เอกสารนี้อธิบาย **คอนเซปต์ผลิตภัณฑ์ของ PEA** โค้ดที่มีอยู่ในเช็กเอาต์ปัจจุบันคือเครื่องมือวิศวกรรมย้อนกลับ (`rea-agents`) ซึ่งยังไม่ได้พัฒนาฟีเจอร์การเก็บข้อมูลและการควบคุมที่กล่าวมาข้างต้น ชื่อคำสั่ง รายการเชื่อมต่อ และค่าเกณฑ์จะสรุปพร้อมกับการพัฒนา README ฉบับแปลยังอ้างอิงเอกสารเวอร์ชันก่อนหน้า จึงจะทยอยปรับปรุงให้สอดคล้องกับการรีแบรนด์
