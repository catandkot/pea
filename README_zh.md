# 🫛 PEA

### 智慧农场代理 —— 读取田间数据、做出判断、执行动作。

PEA（豌豆）是面向温室与露地栽培现场的**智慧农场代理**。它汇集土壤水分、温湿度、日照量、CO2、排液 EC/pH 等传感器数值，解释*当下正在发生什么*，并在**安全限值之内**控制灌溉、通风、遮光、补光等执行器。

每项判断都附带依据。PEA 会区分**观测值**、**推断值**和**尚不知道的值**再作汇报。“土壤偏干”是传感器历史，“午后真菌感染风险高”是推断，而“灌溉阀门是否真的打开了”在有流量计确认之前仍是未知。

所有作业都在农场内部完成。传向外部的数据只有用户明确选定的项目。

## 它能做什么

| 领域 | PEA 做的事 | 使用的数据 |
| --- | --- | --- |
| 生育环境 | 展示温室内温湿度、VPD、日照累积的走势与异常区间 | 温湿度传感器、日照计 |
| 灌溉·营养液 | 依据日照累积量计算灌溉量，对排液率偏离目标发出警报 | 土壤水分·重量计、排液 EC/pH |
| 通风·冷暖 | 维持 VPD 目标的控制，提出通风窗与风机档位建议 | 开窗度反馈、室外气象 |
| 病虫害预警 | 结合叶面湿润持续时长与温湿度组合推算真菌病害风险 | 温湿度历史、叶面湿润传感器 |
| 生育日志 | 自动记录灌溉、环境与农事历史，辅助录入生育调查数据 | 作业日志、现场照片 |
| 收获预测 | 基于积温推算收获时期，比较不同茬口 | 气温历史、品种参数 |

表中的项目和阈值都是**需要按作物、品种、地区重新校准的值**。PEA 只提出默认值建议，不会把它当作该农场的基准值来下定论。

## 工作方式

当代理通过 MCP 向 PEA 提问时，PEA 会从网关汇集数据，连同依据一起返回结果。代理据此说明情况或给出控制方案。同一套工作流在终端的 CLI 中同样适用。

```text
智能体 → MCP → PEA → 网关 → 传感器
             ← 观测值 + 推断 + 未知
```

- **本地优先** —— 采集与判断都在农场内部处理。
- **依据优先** —— 结论会连同原始数值、时间和来源一并留存。
- **未知就是未知** —— 没有传感器或通信中断的区间，不用估算填补，而是明确标注出来。
- **结果一致** —— CLI 与 MCP 共享同一套工作流和同一份结果契约。

## 安全原则

移动执行器是无法撤销的。因此 PEA 遵守以下原则。

1. **以人工批准为默认** —— 灌溉、通风、补光等实际动作会先输出计划，再取得批准。
2. **硬性钳制** —— 农场设定的上限（单次最大灌溉量、允许温度范围等）无法被代理的判断突破。
3. **失效安全** —— 通信中断或停电时会落到安全一侧（停止灌溉、打开通风等）。
4. **喷洒不自动化** —— 农药与肥料喷洒不由 PEA 执行，只提出时机与依据。
5. **全程记录** —— 每次控制都留下对象、时间、依据和执行结果。
