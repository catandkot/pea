# 🫛 PEA

### 智慧農場代理 — 讀懂栽培現場的資料，做出判斷，並採取行動。

**感測器早就在說話了，PEA 讓這些訊息能被聽懂。**

PEA（豌豆）是為溫室與露天栽培現場打造的**智慧農場代理**。它會蒐集土壤水分、溫濕度、日射量、CO2、排液 EC/pH 等感測器數值，說明*當下正在發生的事*，並在**安全限度內**控制灌溉、通風、遮光、補光等致動器。

每一項判斷都附帶依據。PEA 會區分並回報**觀測到的數值**、**推論出的數值**與**目前仍未知的數值**。「土壤偏乾」來自感測器歷史紀錄，「午後發生萎凋的風險偏高」屬於推論，而「灌溉閥是否真的開啟」在流量計確認之前都是未知。

所有作業都在農場內部完成。會傳到外部的資料，只有使用者明確選擇的項目。

## 快速開始

> **以下指令與套件名稱尚未定案。** 目前 npm 上並沒有已發布的 `pea` 套件。正式發布時，我們會把這份文件更新為實際可用的指令。

```bash
# 1) install (package not published yet)
npx pea-agents setup

# 2) readiness check — gateway, sensors and actuators
pea doctor

# 3) ask about today's greenhouse
pea analyze ./farm.toml
```

接上代理之後，就可以這樣提問。

```text
3 號溫室上午的灌溉量比目標多了 12%，原因是什麼？
要把排液率調整到 25%，今天下午的灌溉排程該怎麼改？
請顯示以昨晚最低氣溫為基準，葉面濕潤持續了幾個小時。
```

## 功能範疇

| 領域 | PEA 負責的事 | 使用的資料 |
| --- | --- | --- |
| 生育環境 | 顯示溫室內溫濕度、VPD、日射量累積趨勢與異常區間 | 溫濕度感測器、日射計 |
| 灌溉與養液 | 依日射量累積計算灌溉量，並在排液率偏離目標時發出警示 | 土壤水分計、重量計、排液 EC/pH |
| 通風與溫控 | 控制以維持 VPD 目標，並建議通風窗與風扇段數 | 通風窗開度回饋、室外氣象 |
| 病蟲害警示 | 以葉面濕潤持續時間與溫濕度組合計算真菌病害風險 | 溫濕度歷史、葉面濕潤感測器 |
| 栽培日誌 | 自動記錄灌溉、環境與作業歷程，並協助輸入生育調查 | 作業紀錄、現場照片 |
| 收穫預測 | 依積算溫度推估收穫時機，並比較不同期作 | 氣溫歷史、品種參數 |

表中的項目與閾值都是**必須依作物、品種與地區重新校準的數值**。PEA 只會提出預設值建議，不會把它當成該農場的標準值。

## 運作方式

當代理透過 MCP 向 PEA 提問，PEA 會從閘道器蒐集資料，連同依據一起回傳結果。代理再根據結果說明現況或提出控制方案。同一套工作流程也可以直接在終端機的 CLI 中使用。

```text
代理 → MCP → PEA → 閘道器 → 感測器
                  ← 觀測值 + 推論 + 未知
```

- **本機優先** — 資料蒐集與判斷都在農場內部完成。
- **依據優先** — 結論會一併留下原始數值、時間與來源。
- **未知就標示為未知** — 沒有感測器或通訊中斷的區間，不會用推估填補，而是明確標示。
- **一致的結果** — CLI 與 MCP 共用相同的工作流程與結果契約。

## 安全原則

驅動致動器的動作無法復原。因此 PEA 遵守以下原則。

1. **以人工核准為預設** — 灌溉、通風、補光等實際動作，會先輸出計畫並取得核准。
2. **硬性上限** — 農場設定的上限（單次最大灌溉量、允許溫度範圍等）不會因為代理的判斷而被突破。
3. **失效安全** — 通訊中斷或停電時，會回到安全側（停止灌溉、開啟通風等）。
4. **不自動化噴施作業** — 農藥與肥料的噴施不由 PEA 執行，只提出時機與依據。
5. **完整記錄** — 每次控制都會留下對象、時間、依據與執行結果。
