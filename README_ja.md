# 🫛 PEA

### スマートファームエージェント — 栽培現場のデータを読み、判断し、実行します。

PEA（豆）は、温室と露地栽培の現場のための**スマートファームエージェント**です。土壌水分、温湿度、日射量、CO2、排液 EC/pH といったセンサー値を集めて *いま何が起きているのか* を説明し、灌水・換気・遮光・補光といったアクチュエータを**安全限界の範囲内で**制御します。

すべての判断には根拠が伴います。PEA は**観測した値**、**推論した値**、**まだ分からない値**を区別して報告します。「土壌が乾燥している」はセンサー履歴であり、「午後は萎凋のリスクが高い」は推論であり、「灌水バルブが実際に開いたかどうか」は流量計が確認するまで不明です。

作業は農場の中で完結します。外部に出ていくデータは、ユーザーが明示的に選んだ項目だけです。


## できること

| 領域 | PEA が行うこと | 使用するデータ |
| --- | --- | --- |
| 生育環境 | 温室内の温湿度、VPD、日射量積算の推移と異常区間の表示 | 温湿度センサー、日射計 |
| 灌水・養液 | 日射量積算に基づく灌水量の算出、排液率の目標に対する偏差の警告 | 土壌水分・重量計、排液 EC/pH |
| 換気・冷暖房 | VPD 目標を維持する制御、換気窓・ファンの段階提案 | 窓開度フィードバック、外気の気象 |
| 病害虫警報 | 葉面湿潤の継続時間と温湿度の組み合わせから糸状菌病のリスクを算出 | 温湿度履歴、葉面湿潤センサー |
| 栽培日誌 | 灌水・環境・作業の履歴を自動記録し、生育調査の入力を補助 | 作業ログ、現場写真 |
| 収穫予測 | 積算温度に基づく収穫時期の推定、作期の比較 | 気温履歴、品種パラメータ |

表の項目と閾値は、**作物・品種・地域ごとに再キャリブレーションが必要な値**です。PEA は初期値を提案するだけで、それをその農場の基準値だと断定はしません。

## 仕組み

エージェントが MCP で PEA に問い合わせると、PEA はゲートウェイからデータを集め、根拠とともに結果を返します。エージェントはその結果をもとに状況を説明したり、制御案を提示したりします。同じワークフローはターミナルの CLI でもそのまま使えます。

```text
エージェント → MCP → PEA → ゲートウェイ → センサー
                       ← 観測値 + 推論 + 不明
```

- **ローカル優先** — 収集と判断は農場の中で処理します。
- **根拠優先** — 結論とともに元の値、時刻、出所を残します。
- **不明は不明のまま** — センサーがない区間や通信が途切れた区間を推測で埋めず、明示します。
- **同じ結果** — CLI と MCP が同じワークフローと同じ結果契約を共有します。

## 安全原則

アクチュエータを動かす操作は元に戻せません。そのため PEA は次のことを守ります。

1. **人の承認が基本** — 灌水・換気・補光といった実際の動作は、まず計画を出力して承認を得ます。
2. **ハードクランプ** — 農場に設定した上限（1 回あたりの最大灌水量、許容温度範囲など）は、エージェントの判断で超えることはできません。
3. **フェイルセーフ** — 通信断や停電のときは安全側（灌水停止、換気開放など）に倒れます。
4. **散布は自動化しない** — 農薬・肥料の散布は PEA が実行せず、時期と根拠だけを提案します。
5. **全量記録** — すべての制御に、対象、時刻、根拠、実行結果を残します。

## ロードマップ

- **M0 — コンセプトとドキュメント** *(現在)*: 製品定義、安全原則、結果契約の設計
- **M1 — 収集**: ゲートウェイ連携、センサー履歴の保存、環境推移の照会
- **M2 — 助言**: 灌水・換気アドバイザー、病害虫リスク、栽培日誌の自動化
- **M3 — 承認ベースの制御**: 人の承認下での自動制御とフェイルセーフ
- **M4 — 運用**: 収穫予測、複数農場の比較、作期レポート
