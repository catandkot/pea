# 🫛 PEA

### 스마트 팜 에이전트 — 재배 현장의 데이터를 읽고, 판단하고, 실행합니다.

**센서는 이미 말하고 있습니다. PEA가 그 말을 알아듣게 해줍니다.**

PEA(콩)는 온실과 노지 재배 현장을 위한 **스마트 팜 에이전트**입니다. 토양 수분, 온·습도, 일사량, CO2, 배액 EC/pH 같은 센서 값을 모아 *지금 벌어지고 있는 일*을 설명하고, 관수·환기·차광·보광 같은 액추에이터를 **안전 한도 안에서** 제어합니다.

모든 판단에는 근거가 따라붙습니다. PEA는 **관측한 값**, **추론한 값**, **아직 모르는 값**을 구분해서 보고합니다. "토양이 건조하다"는 센서 이력이고, "오후에 위조 위험이 높다"는 추론이며, "관수 밸브가 실제로 열렸는지"는 유량계가 확인해 주기 전까지 미지입니다.

작업은 농장 안에서 끝납니다. 외부로 나가는 데이터는 사용자가 명시적으로 고른 항목뿐입니다.

## 빠른 시작

> **아래 명령과 패키지 이름은 아직 확정 전입니다.** 현재 npm에 배포된 `pea` 패키지는 없습니다. 배포 시점에 이 문서를 실제 명령으로 갱신합니다.

```bash
# 1) install (package not published yet)
npx pea-agents setup

# 2) readiness check — gateway, sensors and actuators
pea doctor

# 3) ask about today's greenhouse
pea analyze ./farm.toml
```

에이전트에 연결한 뒤에는 이렇게 물어보면 됩니다.

```text
3번 온실 오전 관수량이 목표보다 12% 많았어. 원인이 뭐야?
배액률을 25%로 맞추려면 오늘 오후 관수 스케줄을 어떻게 바꿔야 해?
어젯밤 최저기온 기준으로 잎 습윤 지속 시간이 몇 시간이었는지 보여줘.
```

## 무엇을 하는가

| 영역 | PEA가 하는 일 | 쓰이는 데이터 |
| --- | --- | --- |
| 생육 환경 | 온실 내 온·습도, VPD, 일사량 적산 추이와 이상 구간 표시 | 온습도 센서, 일사량계 |
| 관수·양액 | 일사량 적산 기반 관수량 산정, 배액률 목표 대비 편차 경보 | 토양 수분·중량계, 배액 EC/pH |
| 환기·냉난방 | VPD 목표 유지 제어, 환기창·팬 단계 제안 | 창 개도 피드백, 외기 기상 |
| 병해충 경보 | 잎 습윤 지속 시간과 온습도 조합으로 곰팡이병 위험도 산출 | 온습도 이력, 잎 습윤 센서 |
| 생육 일지 | 관수·환경·작업 이력 자동 기록, 생육 조사 입력 보조 | 작업 로그, 현장 사진 |
| 수확 예측 | 적산 온도 기반 수확 시기 추정, 작기 비교 | 기온 이력, 품종 파라미터 |

표의 항목과 임계값은 **작물·품종·지역마다 다시 캘리브레이션해야 하는 값**입니다. PEA는 기본값을 제안할 뿐, 그 농장의 기준값으로 단정하지 않습니다.

## 작동 방식

에이전트가 MCP로 PEA에 질문하면, PEA는 게이트웨이에서 데이터를 모아 근거와 함께 결과를 돌려줍니다. 에이전트는 그 결과로 상황을 설명하거나 제어안을 제시합니다. 같은 워크플로를 터미널의 CLI에서도 그대로 씁니다.

```text
에이전트 → MCP → PEA → 게이트웨이 → 센서
                     ← 관측값 + 추론 + 미지
```

- **로컬 우선** — 수집과 판단은 농장 안에서 처리합니다.
- **근거 우선** — 결론과 함께 원본 값, 시각, 출처를 남깁니다.
- **미지를 미지로** — 센서가 없거나 통신이 끊긴 구간을 추정으로 메우지 않고 명시합니다.
- **동일한 결과** — CLI와 MCP가 같은 워크플로와 같은 결과 계약을 공유합니다.

## 지원 대상

| 연동 | 방식 | 상태 |
| --- | --- | --- |
| MQTT 게이트웨이 | 브로커 구독으로 센서 토픽 수집 | 계획 |
| Modbus RTU / TCP | 제어기 레지스터 폴링 | 계획 |
| LoRaWAN | 게이트웨이 경유 노지 센서 | 계획 |
| 기상 데이터 | 지역 기상 API, 외기 온·습도·강수 | 계획 |
| 기존 재배 관리 시스템 | 파일 가져오기(CSV/JSON)로 이력 병합 | 계획 |

## 안전 원칙

액추에이터를 움직이는 일은 되돌릴 수 없습니다. 그래서 PEA는 다음을 지킵니다.

1. **사람 승인 기본** — 관수·환기·보광 같은 실제 동작은 계획을 먼저 출력하고 승인을 받습니다.
2. **하드 클램프** — 농장에 설정한 상한(1회 최대 관수량, 허용 온도 범위 등)은 에이전트 판단으로 넘을 수 없습니다.
3. **페일세이프** — 통신 단절이나 정전 시에는 안전 측(관수 정지, 환기 개방 등)으로 떨어집니다.
4. **살포는 자동화하지 않음** — 농약·비료 살포는 PEA가 실행하지 않고, 시기와 근거만 제안합니다.
5. **전량 기록** — 모든 제어에 대상, 시각, 근거, 실행 결과를 남깁니다.

## 로드맵

- **M0 — 콘셉트와 문서** *(현재)*: 제품 정의, 안전 원칙, 결과 계약 설계
- **M1 — 수집**: 게이트웨이 연동, 센서 이력 저장, 환경 추이 조회
- **M2 — 조언**: 관수·환기 어드바이저, 병해충 위험도, 생육 일지 자동화
- **M3 — 승인 기반 제어**: 사람 승인 하의 자동 제어와 페일세이프
- **M4 — 운영**: 수확 예측, 다농장 비교, 작기 리포트

## 프로젝트 상태

이 문서는 **PEA의 제품 콘셉트**를 설명합니다. 현재 체크아웃에 들어 있는 코드는 역공학 도구(`rea-agents`)이며, 위에 적힌 수집·제어 기능을 아직 구현하지 않았습니다. 명령 이름, 연동 목록, 임계값은 구현과 함께 확정됩니다. 번역 README는 아직 이전 문서를 기준으로 하고 있어, 리브랜딩에 맞춰 순차적으로 정비합니다.
