# 🫛 PEA

### وكيل المزارع الذكية — يقرأ بيانات موقع الزراعة، ويتخذ القرارات، وينفّذها.

PEA (البازلاء) هو **وكيل مزرعة ذكية** للبيوت المحمية والحقول المكشوفة. يجمع قيم المستشعرات مثل رطوبة التربة ودرجة الحرارة والرطوبة النسبية والإشعاع الشمسي وCO2 وEC/pH في محلول الصرف، ليشرح *ما يجري الآن*، ويتحكم في المشغّلات مثل الري والتهوية والتظليل والإضاءة التكميلية **ضمن حدود آمنة**.

كل قرار ترافقه حجّته. يميّز PEA بين **القيم المرصودة** و**القيم المستنتجة** و**القيم التي لا يزال يجهلها**، ويبلّغ عنها على هذا الأساس. فقول "التربة جافة" حقيقة من سجل المستشعرات، و"خطر الذبول مرتفع بعد الظهر" استنتاج، أما "هل فُتح صمام الري فعلًا؟" فيبقى مجهولًا حتى يؤكده مقياس التدفق.

العمل كله ينتهي داخل المزرعة. والبيانات التي تخرج إلى الخارج هي فقط العناصر التي يختارها المستخدم صراحةً.

## البدء السريع

> **أسماء الأوامر والحزم أدناه لم تُعتمد نهائيًا بعد.** لا توجد حاليًا حزمة `pea` منشورة على npm. وسنحدّث هذا المستند بالأوامر الفعلية عند الإطلاق.

```bash
# 1) install (package not published yet)
npx pea-agents setup

# 2) readiness check — gateway, sensors and actuators
pea doctor

# 3) ask about today's greenhouse
pea analyze ./farm.toml
```

بعد ربط الوكيل، يكفي أن تسأله هكذا.

```text
كمية الري الصباحية في البيت المحمي رقم 3 كانت أعلى من الهدف بنسبة 12%. ما السبب؟
كيف أغيّر جدول ري بعد الظهر اليوم لضبط نسبة الصرف عند 25%؟
أظهر لي عدد ساعات استمرار بلل الورقة بناءً على أدنى حرارة ليلة أمس.
```

## ما الذي يفعله

| المجال | ما يفعله PEA | البيانات المستخدمة |
| --- | --- | --- |
| بيئة النمو | اتجاه تراكم درجة الحرارة والرطوبة داخل البيت المحمي وVPD والإشعاع الشمسي، مع تحديد الفترات الشاذة | مستشعرات الحرارة والرطوبة، مقياس الإشعاع الشمسي |
| الري والتغذية | تقدير كمية الري بناءً على تراكم الإشعاع الشمسي، وتنبيه عند انحراف نسبة الصرف عن الهدف | رطوبة التربة وميزان الوزن، EC/pH الصرف |
| التهوية والتبريد والتدفئة | التحكم للحفاظ على هدف VPD، واقتراح مراحل فتح النوافذ والمراوح | تغذية راجعة لفتحة النافذة، الطقس الخارجي |
| إنذار الآفات والأمراض | حساب خطر الأمراض الفطرية من مدة بلل الورقة ومزيج الحرارة والرطوبة | سجل الحرارة والرطوبة، مستشعر بلل الورقة |
| سجل النمو | تسجيل تلقائي لتاريخ الري والبيئة والعمليات، ومساعدة في إدخال بيانات فحص النمو | سجل العمليات، صور الموقع |
| توقع الحصاد | تقدير موعد الحصاد بناءً على تراكم الحرارة، ومقارنة المواسم | سجل الحرارة، معاملات الصنف |

قيم الجدول وحدوده العتبية **قيم تحتاج إلى معايرة جديدة لكل محصول وصنف ومنطقة**. ويقتصر PEA على اقتراح القيم الافتراضية، ولا يجزم بأنها القيم المعيارية لتلك المزرعة.

## كيف يعمل

عندما يسأل الوكيل PEA عبر MCP، يجمع PEA البيانات من البوابة ويعيد النتيجة مع الأدلة. وعلى أساسها يشرح الوكيل الوضع أو يقترح خطة تحكم. ويمكن استخدام المسار نفسه تمامًا من CLI في الطرفية.

```text
الوكيل → MCP → PEA → البوابة → المستشعرات
                   ← القيم المرصودة + الاستنتاج + المجهول
```

- **محلي أولًا** — تُنجَز عمليات الجمع والتحليل داخل المزرعة.
- **الأدلة أولًا** — تُحفظ القيم الأصلية والوقت والمصدر مع الاستنتاج.
- **المجهول يبقى مجهولًا** — الفترات التي لا يوجد فيها مستشعر أو ينقطع فيها الاتصال تُعلَن صراحةً ولا تُملأ بالتخمين.
- **النتيجة نفسها** — يشترك CLI وMCP في المسار نفسه وعقد النتائج نفسه.

## ما ندعمه

| التكامل | الطريقة | الحالة |
| --- | --- | --- |
| بوابة MQTT | جمع مواضيع المستشعرات عبر الاشتراك في الوسيط | مخطَّط |
| Modbus RTU / TCP | استقصاء سجلات وحدة التحكم | مخطَّط |
| LoRaWAN | مستشعرات الحقول المكشوفة عبر البوابة | مخطَّط |
| بيانات الطقس | واجهة الطقس الإقليمية، الحرارة والرطوبة والهطول الخارجية | مخطَّط |
| أنظمة إدارة الزراعة القائمة | دمج السجل عبر استيراد ملفات (CSV/JSON) | مخطَّط |

## مبادئ السلامة

تحريك المشغّلات فعل لا رجعة فيه. لذلك يلتزم PEA بما يلي.

1. **موافقة الإنسان هي الأصل** — قبل أي فعل حقيقي مثل الري أو التهوية أو الإضاءة التكميلية، تُطبع الخطة أولًا ويُطلب الاعتماد.
2. **حدود صارمة** — لا يمكن لتقدير الوكيل أن يتجاوز الحدود المضبوطة للمزرعة (أقصى كمية ري في المرة، ونطاق الحرارة المسموح، وغيرها).
3. **الوضع الآمن عند الفشل** — عند انقطاع الاتصال أو انقطاع الكهرباء ينزلق النظام إلى الجانب الآمن (إيقاف الري، وفتح التهوية، وغير ذلك).
4. **الرشّ لا يُؤتمَت** — لا ينفّذ PEA رشّ المبيدات أو الأسمدة، بل يقترح التوقيت والأدلة فقط.
5. **تسجيل كامل** — يُسجَّل لكل عملية تحكم الهدف والوقت والدليل ونتيجة التنفيذ.

## خارطة الطريق

- **M0 — المفهوم والتوثيق** *(الحالي)*: تعريف المنتج، ومبادئ السلامة، وتصميم عقد النتائج
- **M1 — الجمع**: ربط البوابة، وتخزين سجل المستشعرات، والاستعلام عن اتجاهات البيئة
- **M2 — المشورة**: مستشار الري والتهوية، وخطر الآفات والأمراض، وأتمتة سجل النمو
- **M3 — تحكم قائم على الموافقة**: تحكم تلقائي بموافقة الإنسان مع الوضع الآمن عند الفشل
- **M4 — التشغيل**: توقع الحصاد، ومقارنة عدة مزارع، وتقارير الموسم

## حالة المشروع

يشرح هذا المستند **المفهوم المنتَجي لـ PEA**. أما الشيفرة الموجودة في النسخة الحالية فهي أداة هندسة عكسية (`rea-agents`) ولم تنفّذ بعد وظائف الجمع والتحكم المذكورة أعلاه. وستُعتمد أسماء الأوامر وقائمة التكاملات والحدود العتبية مع التنفيذ. ولا تزال ملفات README المترجمة مبنية على المستند السابق، وسنحدّثها تباعًا بما يوافق إعادة التسمية.
